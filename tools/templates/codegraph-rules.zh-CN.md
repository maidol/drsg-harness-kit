## 代码图（结构性问题必须先查图）

本仓库已折叠到 **`@PLANE@`** 平面，每次提交都会重新折叠，并由
`drsg-watch` MCP 工具通过 `http://@ADDR@/mcp` 提供服务。图中建模了：@LABELS@。
如需查看当前规模和同步到的提交，请调用 `describe_plane`，或运行
`@CTL@ status --dir @REPO@`——这里不写入计数，因为文档中的计数下一个提交就会过期。

**每次调用都必须传 `plane: "@PLANE@"`。** 工具默认使用空的 `startup` 平面，返回的
`no symbol matches` 无法与图确实不知道该符号区分。在本配置的第一次审计中，8 个空回答
里有 6 个是平面寻址错误，真正的数据缺口只有 2 个。

**检查答案时必须使用代码图自己的符号 key。** 结构性结论必须引用图返回的完整 key——
例如 `crate::module::Symbol`、`github.com/acme/example/pkg.Type.Method`——不能只引用
`file:line`，因为 grep 也会打印 `file:line`，这样的规则无法发现自身违反了约束。

**触发条件在答案里，不在问题里。** 只要回答包含量化的结构性结论——“只有 X 个调用者”、
“没有任何地方使用它”、“不会影响其他地方”、“需要修改这些位置”——该结论就必须来自
代码图，不论提问本身听起来多么随意。

| 问题 | 动词 |
|---|---|
| 谁调用 X／一次查看 X 的全部关系 | `context`（从这里开始） |
| 修改 X 会影响什么 | `impact` |
| A 如何到达 B | `trace` |
| X 在哪里、签名是什么 | `describe` |
| 给我 X 的源码 | `snippet` |
| 这个平面里有什么 | `describe_plane`、`cypher` |
| 图没有建模的文本 | `grep`（搜索受监视的源树） |

**涉及变更的问题必须先运行 `impact`。** 询问修改、重命名或删除 X 会影响什么，与询问谁
调用 X 是不同的问题；`context` 只走一跳，不能回答前者。任何关于变更影响面的回答都
必须引用 `impact`，它会按距离分组并给出每组计数；调用者清单没有这种形状，用清单替代是
可见的错误。`impact` 在距离 1 之后没有返回内容本身就是答案，要明确说出。它只统计已记录
的边，工具也会说明这一点——引用计数时必须带上“这是下限”的限定。`trace` 同样如此：
声称 A 到达 B 时，必须逐跳引用 `trace` 返回的路径。

要预期自己会违反这条规则。本配置上线第一个月里，`context` 被调用 46 次，`impact` 只有
1 次，`trace` 是 0 次——所有影响面问题都被只看一跳的动词回答了，但当时没有一个答案
看起来明显错误。

**使用符号名提问，不要使用描述。** `context` 按三步解析字符串（精确 key、`::name`／
`.name` 后缀、再到不区分大小写的子串）。提供文件名会进入 `Read`，提供符号名才会查图。
第三步是边界：描述性词语只有在确实是某个符号名的子串时才有效，例如 `plugin` 可以解析；
自然语言描述——或者代码语言之外的文字——不行。这是 `grep` 的职责，回答中必须说明
这一点。

**候选超过 20 个时不要从清单中挑。** 候选清单最多显示前 20 个，且**不按相关性排序**；
如果候选太多，应该收窄后重新查询，因为正确符号可能在被截断的部分。通常用
`Type::method` 收窄，往往能一次命中。候选有 2–10 个时，先分别运行 `describe` 查看签名
再选择：返回另一个 crate 类型的函数通常是包装层，对包装层运行 `impact` 得到的影响面
会严格小于它所委托的真实实现。

**把 `impact` 的深度加到某一层返回空。** 默认深度是 3；如果传播还没有停止就截断，得到
的只是“前三跳”而不是完整影响面，不同深度的两个符号也不可比较。出现空层才是答案完整
的证据。

**代码图也会明确告诉你它不知道。** `UnresolvedRef` 节点正是解析器放弃解析的地方（数量
可由 `describe_plane` 查看），跨语言边通常也无法建立。注释（`//`）、字符串字面量以及
插件没有声明的文件（`.md`、`.sh`、CI 配置）都不会建模。遇到这些内容请使用 `grep`，并
明确说明答案来自 grep——图返回空不是凭印象补答案的理由。

Daemon：`@CTL@ {start|stop|restart|status|rules} --dir @REPO@`。每个仓库一个 daemon；
地址和 token 都在 `.mcp.json` 中，因此不要自行生成 token——新 token 会使 `drsg init` 已
写入的所有客户端配置失效。
