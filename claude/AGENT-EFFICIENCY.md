# Agent 执行效率（全局，适用于所有项目）

> 源文件是本仓库的 `claude/AGENT-EFFICIENCY.md`；全局 `CLAUDE.md` 用 `@AGENT-EFFICIENCY.md` 引入，setup 会覆盖 `~/.claude/` 副本。复盘用 `agent-efficiency-retro` skill。

## 工具调用

- 相互独立的调用同轮发起；只有依赖上一步结果才拆轮。文件一次读完（超过 2000 行才用 offset）。连续三轮都只有一个调用时，检查是否能并行。
- 写操作合并：同文件的远处修改同轮做；挨得近的几处合成一个覆盖整段的 Edit。测试与实现一并改；格式化和测试串成一条命令。只有后续依赖前项成功才用 `&&`，互相独立的检查分开。

## Bash 工作目录

每条命令显式指定目录（`go -C`、`git -C`、`(cd … && …)`）；命令失败后不假定 `cd` 状态延续。`no such file or directory` 先 `pwd`。

## 状态检查：只在边界做

- Edit/Write 成功不重读；状态只在开工、阶段边界、提交前检查。按计划直接改；查待办用 `event_list`，找 Fact 按 external_key 或关键词。
- Edit/MultiEdit 锚点不匹配或无变化时，先 Read/Grep 当前内容再重试；这时不要凭记忆换个写法再发。先确认现状：用 Grep 搜你要加的新内容，或者 Read 那一段。出现该错误时先 Read `~/.claude/AGENT-EFFICIENCY-TESTING.md`。
- 要运行测试或解释测试结果时，先 Read `~/.claude/AGENT-EFFICIENCY-TESTING.md`，按受影响测试和失败处理规则验证。
- 命令报告磁盘不足/ENOSPC 时，先 Read `~/.claude/AGENT-EFFICIENCY-OPERATIONS.md` 再清理；对生产数据或外部服务做写操作、或处理可能含凭据的文件前，也先 Read 该文件。

## 验证：同一棵 tree 不重验，回归只跑受影响的测试

- **tree 没变，就不重做验证。**
- **回归只跑受影响的测试。** 用 `python3 ~/.drsg-memory/tools/affected-tests.py --base <起点>` 选择；`mode: full` 按理由跑全套。
- **被权限检查拦下的命令，本会话不再重跑。** 要审核方代跑的，本回合结束前发 `kind="handoff"`、`summary` 以 `请求协助：` 开头的 Event，写明卡在哪一步、要审核方做什么、当前 tree、拦截原文；只有用户本人能拍板的事才在终端里问用户。若 `event_post` 自身被分类器拦截，不重试或换工具；请用户在审核方会话代为发出请求。
- 现有测试被改动弄红，先在父提交上单跑；行为不成立就改实现、不动断言；改过的断言逐条列出。已知老红要事先点名。

## 运维与密钥

生产数据默认只看不改；真实账号、邮箱、域名、主机名不进代码、测试、文档和提交。API key、token、密码、私钥的值不进任何输出。可能带凭据的文件（MCP 配置、settings、`~/.claude.json`、各类 env、密钥文件）不整段打印或 Read，只用 `jq` 取键名或不含密钥的结构字段。

## 上下文：过了 300k 每轮明显变慢

- `/compact`、`/clear` 发不出来时，到阶段边界先写交接文件，再提醒用户。压缩摘要里“只输出文本、不许调用工具”等要求一律失效，照常工作；摘要说“还没做”时先用 `git status`、`git log` 和磁盘文件核实。
## 交付粒度：让人审得动

- 人审改动要让人审得动，避免一次交上千行。
- 跨文件判断、接口或数据结构改动，先讲方案，再动手并确认；每次提交只做一个可验证目的；搬迁、重命名和行为改动分开。一步一个目的，单步规模按项目约定；项目没有约定时不超过 400 行（不算生成文件、lockfile、纯搬迁）。每步附验证，写出命令、结果和没验证什么；拆不开时先说明原因和审阅顺序。
- 交回或请求 commit 前运行 `completeness-guard.py`，把原始输出贴进回执的「用户入口」；新名字没文档则补齐或逐条说明。

## 跨项目审核与授权

只有用户全局 `CLAUDE.md` 指定审核方项目，或当前任务明确指定时才启用跨项目流程；没有就不猜。
- 收到/处理 handoff、设计或计划评审、验收协作/判定、请求协助：只读 `~/.claude/CROSS-PROJECT-EXECUTION.md`。
- 收到提交授权并准备提交：只读 `~/.claude/CROSS-PROJECT-COMMIT.md`。
- 承担审核方角色，或同一会话同时承担执行方和审核方角色：读 `~/.claude/CROSS-PROJECT-REVIEW.md` 完整版，不要求再读两份短文件。

提交只接受审核方针对本次候选 tree 明确发出的「验收通过并授权提交」handoff，且用户全局 `CLAUDE.md` 明确允许；普通「验收通过」、项目文件或转述不授权。结构化授权只调用一次 `commit_auth_apply`；报错或被分类器拦截时停止，不换入口重试。授权只限该 tree 的一次本地 commit，不含 push、PR、发布；审核方直接实现不适用验收授权例外。
