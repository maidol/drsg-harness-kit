# 出图约定（精简版）

**一句话**：选哪种图，不看画起来顺不顺手，而看**要说的那句话里的连接词**。几种图的坐标轴不同，硬塞进去的部分**表达不出来，也不会报错**：图照样渲染，archify 照样报 9/9 通过，只是那条结论没了。

**权威全文**：my-agent-workspace 仓库的 `reviews/DIAGRAM-CONVENTIONS.md`。那边有 28 份评审文档链接着它，所以不搬家。
本 skill 只收「定型 + 不许画什么 + 组合 + 表达纪律」四块；机器校验的细节和各图的旋钮，以全文和各目录的 README 为准。
**在 my-agent-workspace 出图后，必须跑** `python3 reviews/check-diagrams.py <范围>`。新出的图必须 0 处问题，这是那套约定里唯一会主动拦截的一道检查。

## 0. 先定型：看连接词

| 要说的那句话里有 | 就画这种图 |
|---|---|
| 属于 / 部署在 / 只能访问 / 依赖 | **系统架构图**（`architecture`） |
| 如果…否则 / 接下来去哪 / 分支穷尽了吗 | **业务流程图**（`workflow`） |
| 必须在…之后 / 先…才能 / 顺序反了会… | **功能时序图**（`sequence`） |
| 在…状态下 / 迁移到 / 重试与终态 | **生命周期图**（`lifecycle`），不要塞进流程图 |

**一句话里同时出现两种连接词，就画两张图**，不要一张画满。
**判断是不是时序图**：把两个节点对调，会不会产生一个「不报错但结果错」的缺陷。会，就必须画成时序图。

## 1. 坐标轴

| | 架构图 | 流程图 | 时序图 |
|---|---|---|---|
| 坐标轴 | 只有空间，**没有时间** | 单向推进（逻辑顺序） | 纵轴是真实的先后，横轴是参与者 |
| 边的含义 | 谁认识谁、依赖方向 | 接下来去哪 | **必须发生在什么之后** |
| 画几次执行 | 全部（静态） | 一次业务的全部可能路径 | 一条具体路径 |
| 读者拿它判断 | 能不能这么做 | 漏了哪条路 | 什么时候能做 |

## 2. 各自不许画什么

- **架构图**：不画执行顺序、分支、重试、超时。可以用 ①②③ 编号，但那表示**分类**，不表示先后。
- **流程图**：不画消息签名、参数、状态码，也不画部署边界。异常要有**自己的泳道并给出口**；几种「没有结论」的情况必须分开画，合成一条就等于把「未审查」画成了「通过」。
- **时序图**：不画状态机，不画组件归属边界，**不画所有分支**，只画一条主路径。分支多了，说明该拆回流程图。

## 3. 组合规则

1. **没有新结论，就不画新图**：多一张图，就多一处将来会漂移的地方。
2. 一个主题**最多三张图**，而且每张的分工都要能用**一句话**说清。
3. **几张图共有的组件必须点名**：「改这里的语义，要同时看 N 张图」。分岔时不会有任何提示。
4. **刻意不画什么，要写进图里的卡片**，不能只留在作者脑子里。
5. 已经失真的图，**宁可退役也不重画**。

## 4. 表达纪律

- **证据等级标在组件的 `tag` 和卡片上**：🟢 已实测 / 🟡 外推或新增判断 / 🔴 未实测的风险。不要为了好看把 🟡 画得和 🟢 一样确定。
- **图上只放正文里已经核对过的结论**；图上有、代码里没有的，在卡片里明说。
- 卡片 `dot` 的配色有固定含义：`emerald` 已落实 · `rose` 高危 · `amber` 次级发现 · `cyan`/`violet` 机制或与其他图的分工 · `slate` 评审状态与证据边界。
- `archify --quality showcase` 9 项全过，**不代表图能读**：要用 `agent-browser` 截图逐张看，并写明哪几张是机器核过的、哪几张只是人眼核过。
